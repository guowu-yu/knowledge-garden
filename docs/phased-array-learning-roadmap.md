## 六、S5 校准与实时实现（4 篇）　★ 主战场

> **本阶段目标**：让 N 个"各有各的脾气"的通道，像一副天线一样工作。
> **为什么是主战场**：校准的解算、补偿表设计、自动化验证流水线**全是软件问题**——这是软件工程师在这条链路上最容易建立不可替代性的位置。**大部分人会写波束形成算法，但会设计校准流程的人少得多。**

## 八、学习顺序与节奏建议

### 8.1 推荐顺序（七个月分段）

**第 1~2 个月 · S1 + S2 并行（专题 1~8）**
把数学与阵列基础打透。**核心动作是写出那个方向图函数**，然后不停改参数看现象。不要在这一阶段碰硬件手册，会让你陷入细节。

**第 2~4 个月 · S3 略读 + S4 主攻（专题 12~13 速过，17~21 精读）**
S3 用**芯片选型练习**的方式快速过一遍——拿着厂商数据手册反推系统指标，比读教科书快十倍。同时全力投入 S4：写 MVDR、写 MUSIC、上 HLS。

**第 4~6 个月 · S5（专题 25~28）**
校准是软件工程师的**差异化能力**。REV 解算脚本一定要自己写一遍。

**第 6~7 个月 · S6（专题 29~32）**
不需要做实验，需要读懂报告。逐项指标搞清定义与来源。

### 8.2 三条可选捷径（时间紧时）

1. **只做通信波束管理**：S1 → S2 → S3(12) → S4(17, 23, 24)，跳过自适应与校准
2. **只做抗干扰**：S1 → S2 → S4(18, 19, 20) → S5(26)，硬件只读到手册级
3. **只做卫星载荷**：S1 → S2(11 等通量) → S3(16) → S4(21, 22) → S5(26, 27)

### 8.3 最有价值的三个练习（如果只做三件事）

1. **写出方向图函数**，并用它验证 S2 的每一条结论（专题 6~8 的自测）
2. **用 SDR（USRP / PlutoSDR）做一次真实的空口波束成形实验**——从"仿真"到"工程"的断崖式跳跃
3. **写一个 REV 校准解算脚本**，用仿真数据验证它能把误差压到移相器步进以内

## 九、学习路径版误区清单（先记住这几条）

> 完整版见总览篇第九节。这里只列与**学习顺序**直接相关的误区。

**误区一：先把电磁学学精通，再学算法。**
反向。目标是**知道模型的边界**，不是成为天线设计专家。先跑通算法、看到现象，再回头补为什么现实不如仿真。

**误区二：只会仿真，不会定点化。**
浮点仿真通过 ≠ 能上硬件。**定点化和 HLS 综合必须亲手做一遍**，否则在团队里的定位永远停在"算法原型"。

**误区三：把校准当成硬件的活。**
校准的解算、补偿表设计、自动化验证流水线全是软件问题。这是**最容易建立不可替代性**的位置。

**误区四：只关注主瓣，不管副瓣和零陷。**
副瓣决定干扰合规与抗干扰能力。**零陷深度往往比主瓣增益更能体现工程水准**，也是位宽不足时最先暴露的地方。

**误区五：忽略测试，以为"设计对了就一定能过"。**
副瓣、交叉极化、球面覆盖、波束扫描一致性——**恰恰是最常翻车的项**。

**误区六：只学"实时"的一侧，忽略"可维护"。**
在轨校准、自检、故障通道隔离、优雅降级——这些"非功能需求"往往决定产品能不能活到设计寿命。
